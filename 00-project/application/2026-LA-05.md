# Language Learning Assistant with Individual Progress Tracking

## My interpretation of the brief
I interpret this topic as a web application that supports regular language practice and records each learner's individual progress. Learners would complete short exercises, receive feedback, and review the vocabulary or topics that need further practice. The interface would present learning activities and progress summaries, while the backend would store learning content, exercise attempts, and review history separately for each account. I would confirm the detailed requirements and technology constraints against the full published brief before finalising the specification.

## Why I am a good fit for this project
I would approach this project through a clear learning workflow: choose an activity, answer questions, review feedback, and return to material that needs more practice. This provides a manageable scope while requiring meaningful work on interface design, exercise evaluation, persistent data, and individual progress tracking. It also offers concrete behaviour to test and demonstrate, without depending on an unrestricted chatbot or a large collection of learning features.

## Relevant experience and background
I have established a GitHub repository for my project documentation and future source code. I would use this project to develop and demonstrate skills in interactive web interfaces, backend development, relational data modelling, and automated testing. My application does not rely on claims of previous professional language-learning software development; I would address unfamiliar technologies through focused prototypes during the planning phase.

## Proposed approach
I would first define a small set of learning objectives, exercise types, and rules for evaluating answers. Subject to the published brief, the initial scope would cover one language pair and a limited collection of curated vocabulary exercises, using multiple-choice questions and short written answers. Answer checking would use explicit accepted answers and documented handling of case, whitespace, and language-specific characters, rather than treating all spelling variations as equivalent.

I would propose TypeScript with SvelteKit for the interface and backend routes, Prisma for database access, and PostgreSQL for persistence, subject to the brief's requirements. The first complete version would support account access, exercise selection, immediate feedback, saved attempts, and an individual dashboard. A simple rule-based review schedule would prioritise material answered incorrectly and items due for revision. The backend would validate submissions and restrict progress records to their owner. Speech recognition, open-ended AI tutoring, and formal language-level certification would remain outside my proposed initial scope.
